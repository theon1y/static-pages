Синхронизация цепочек · WIP-коммит

Реплицируем эффекты, а не цепочку

Раньше цепочки реплицировались и заново прогонялись на каждом клиенте. Теперь цепочка работает только в авторитетном мире и на предсказывающем клиенте для его собственных действий. Каждый созданный ею эффект синхронизируется отдельно.

Было

Единица синхронизации — цепочка

  • Отправляем id цепочки + сид + источник/цель
  • Каждый клиент сам выполняет таргетинг, тики и дочерние эффекты
  • Поздний вход через LateJoinMode, реализован частично
  • Нет зависимости: ждём до 3 с, потом удаляем
Стало

Единица синхронизации — эффект

  • Таргетинг и тики только в авторитетном мире
  • Удалённые клиенты получают готовые эффекты с источником, целью, позицией и длительностью
  • Поздний вход от StartServerTime: эффекты стартуют со своим реальным возрастом
  • Нет зависимости: PendingEffectData, пока она не разрешится

Сопоставление предсказания с серверным результатом

У владельца серверный эффект приходит, когда клиент уже создал такой же эффект по своему предсказанию. Нужно понять, что это один и тот же эффект, поэтому обе стороны выводят одинаковую идентичность:

EffectChainKey   { ActionTick, Index }          // тик команды + номер цепочки от этого действия
random seed      = hash(RandomBaseSeed(source), ActionTick, Index)
EffectInChainIndex { Stage, Index, SubIndex, Count }
HitKey           = FromEffect(chainKey, inChainIndex, hitNumber)   // или FromAction(tick)
Клиент
Создаёт цепочку с архетипом Predicted (Self + PredictedEffect). Тот же сид — те же броски крита и те же дочерние эффекты.
Сервер
Прогоняет цепочку с тем же ключом, затем SendEffectSystem отправляет каждый эффект по его стратегии.
Принятие
TryAdoptPredicted сопоставляет источник + id эффекта + цель + ключ цепочки + индекс в цепочке. Предсказанный эффект помечается IsConfirmed, пришедшая копия отбрасывается. Серверная реплика остаётся на сущности-держателе, чтобы её время жизни продолжало отслеживаться.
Удаление
Сервер не подтвердил за 1.5 с: DropUnconfirmedPredictedEffectSystem удаляет эффект. Если сервер отклонил скилл, событие кулдауна сразу удаляет всю предсказанную цепочку.

Изменения поменьше

  • Стаки только у авторитетных. EffectStackSystem применяет лимиты стаков только там, где мир считает, или для Self-эффектов. Удалённые эффекты просто кладутся в буфер.
  • Новая стратегия стака Refresh (161 конфиг). Продлевает время жизни существующего эффекта, а не заменяет его, и помечает его для отправки обновления.
  • Удалённые архетипы (Remote, RemoteSelf) без компонентов цепочки, поэтому системы цепочек не трогают реплицированные эффекты.
  • InterpolateEffectPositionSystem сглаживает движущиеся NetworkObject-эффекты, например снаряды.
